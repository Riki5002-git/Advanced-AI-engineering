## 2. השיחות במסד (שלב 3)

```sql
select name,
       count(*) as calls,
       round(avg(duration_ms), 1) as avg_ms,
       round(sum(cost_usd), 4) as cost_usd
from steps
group by name
order by calls desc, name;
```

תוצאה מ־10 תורים: הקריאות הנפוצות ביותר היו למודל `claude-sonnet-5-5` — 32 קריאות, ממוצע 199ms, עלות כוללת 0.1446 דולר. בוצעו 8 קריאות ל־`search_docs` ממוצע 22.2ms, 3 ל־`lookup_warning_code` ממוצע 7.2ms, 2 ל־`check_service_slots` ממוצע 107ms, קריאה אחת ל־`get_price` וקריאה אחת ל־`open_ticket`.

- מה קרה ביום שבו p95 קפץ? לפי `metrics_daily`, ב־2026-11-22 p95 קפץ ל־42,002ms לעומת 6,584ms ביום הקודם ול־7,609ms ביום שאחריו. באותו יום שיעור שגיאות הכלים עלה ל־56.92%, והדרך החזרה הייתה outage ב־CRM שמסומן ב־tool status error וב־timeout/503. הפניה ל־Langfuse עם Level=ERROR מאשרת שהאירוע היה תקלה בכלי ולא באילוץ מדומה של המודל בלבד.
- מה השתנה בין v1.2 ל־v1.3, ואיך זה נראה בנתונים? ב־v1.3 התצורה הייתה מסמכים מלאים במקום קטעים, עם top_k=5 במקום 3. הממוצע בין הגרסאות בדמו היה 0.0067 דולר לתור ב־v1.2 לעומת 0.0087 ב־v1.3, העלייה הייתה 30%. ב־v1.3 עלו גם ממוצע הזמן ל־4,951ms לעומת 4,124ms ושיעור שגיאות הכלים ל־25.24% לעומת 2.10%, בגלל תקופת ה־CRM outage והתגובה שלו. בכך גרסה חדשה מזוהה גם בנתונים וב־Langfuse דרך metadata/release.

## 4. השלב האיטי והשלב היקר (שלב 5)

מדידה לפני ואחרי עם אותם לקוחות ושאותו `seed=1`, `--n 40 --fast`:

| | לפני | אחרי |
|---|---|---|
| השינוי | `SEARCH_FULL_DOCS=True`, `SEARCH_TOP_K=5`, `PARALLEL_SLOT_LOOKUP=False` | `SEARCH_FULL_DOCS=False`, `SEARCH_TOP_K=5`, `PARALLEL_SLOT_LOOKUP=True` |
| זמן תגובה p95 | 0.7 שניות | 0.6 שניות |
| עלות ממוצעת לשיחה | 0.0119 דולר | 0.0105 דולר |
| תורות עם לולאה | 0.0% | 0.0% |
| אגודל למעלה / תשובות עם מקור | 76.2% / 84.1% | 76.2% / 84.1% |

- מהו השלב האיטי ביותר? לפי המדידה של before, השלמת תורים במוסך `check_service_slots` הייתה קריאת הכלי האיטית ביותר עם p95 של 475ms. היא השתפרה ל־279ms לאחר פיצול הריצות במקביל, ירידה של 196ms ב־p95 לקריאת הכלי.
- מהו השלב היקר ביותר? קריאת ה־LLM שאחרי `search_docs` הייתה היקרה ביותר: לפני השינוי 30.9% מכל העלות, ממוצע הקשר 2,876 טוקני קלט. אחרי הקיצור הייתה 23.6%, ממוצע הקשר 1,774 טוקנים. העלות היא בקריאת המודל כי העלות מחושבת מטוקנים של הקשר, ולא מזמן הכלי עצמו.
- איזה שינוי הצעת, מה הוא עלה לך (באיכות, בזמן או בכסף), ואיך יודעים שהוא לא קלקל משהו אחר? הצעתי הקטנת ההקשר שהוחזר מ־`search_docs` ומקביליות ב־`check_service_slots`. העלות הממוצעת ירדה מ־0.0119 ל־0.0105 דולר לשיחה, p95 ירד מ־0.7 ל־0.6 שניות ו־p95 של מוסך ירד מ־475 ל־279ms. אין שינוי ב־loop rate ובאיכות המדודה: `thumbs up` נשאר 76.2% ו־`has source` נשאר 84.1%. שתי הרצות השתמשו באותו `seed=1` ובאותם לקוחות ולכן ההשוואה הייתה מבוקרת. בנוסף השינוי השאיר את רוב התשובות ממסמכים, עם הקטעים הרלוונטיים בלבד.
